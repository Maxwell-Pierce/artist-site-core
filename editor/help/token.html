ARTIST STUDIO / USER GUIDE

GitHub access & connection

Connect the editor to one site repository using a fine-grained personal access token.

Required permissions

SettingChoose
Token typeFine-grained personal access token
Resource ownerThe account or organisation that owns your site repository
Repository accessOnly select repositories → your site repository
Repository permission: ContentsRead and write
Repository permission: MetadataRead-only (included automatically)

You do not need Actions, Workflows, Pages, Administration, Issues or Pull requests permissions for the current editor. Publication is triggered by the content commit, using the repository’s existing workflow.

Create the token

  1. Open GitHub’s fine-grained token creation page, or go to your profile → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
  2. Give the token a recognisable name, such as “Artist Studio”. Choose an expiration date that fits your editing routine.
  3. Choose the correct Resource owner. For an organisation repository, select that organisation rather than your personal account.
  4. Under repository access, select Only select repositories and choose the website repository. You do not need access to the shared core or template just to edit one site.
  5. Under repository permissions, set Contents to Read and write.
  6. Generate the token and copy it. GitHub only displays the newly generated secret once.
  7. If the organisation requires approval, wait for its owner to approve the token. A token cannot grant permissions your own account does not have.

Connect in Studio

Enter the repository as owner/name, without a GitHub URL or .git suffix. Enter the branch deployed by Pages, normally main. Paste the token into the password field and select Connect repository.

The editor verifies that it can read the content and that builder.json enables Studio. A successful connection does not guarantee the branch permits direct writes; repository rules can still reject publication.

Token handling

By default Studio holds the token only in the current tab’s JavaScript memory. To reconnect automatically, select Remember connection on this device before connecting. This stores the repository, branch and token in this browser’s local storage for up to 30 days, renewed when you reconnect. GitHub’s own token expiration and revocation still apply.

Remember only on a device you trust. Scripts running on the same website origin can access this stored credential, so persistent storage is less isolated than an in-memory token. It is never included in drafts, exports or committed content. Disconnect clears the saved connection; Forget saved connection on the connection form also removes it. Closing a tab does not forget a remembered connection.

Local drafts contain content, including unpublished text, and remain in your browser’s local storage. On a shared computer, remove them through the browser’s site-data controls when finished. Draft branches inherit the repository’s visibility; branches in public repositories are public.

Use HTTPS when available. HTTP does not protect the page code from interception, even though API requests go to GitHub over HTTPS. Never paste a token into chat, a page field or a committed configuration file. Revoke a lost or exposed token in GitHub and create a replacement.

Expiration, revocation & organisation rules

An expired, revoked, unapproved or incorrectly scoped token can cause connection or save failures. Create or approve a replacement, export your current work before disconnecting, then reconnect. If the organisation is missing from Resource owner, check your membership and its token policy with the owner.

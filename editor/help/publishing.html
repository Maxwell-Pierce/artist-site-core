ARTIST STUDIO / USER GUIDE

Drafts, publishing & recovery

Keep editing immediate, and make publication a deliberate step.

Local browser recovery

Studio attempts to save changes locally as you edit. The backup is scoped to the repository and published branch. If browser storage is blocked or full, Studio shows a warning; export a backup before leaving.

After refreshing, reconnect to the same repository and branch and select Recover local draft. Recovery is permitted only if the production revision still matches the backup’s base revision. This prevents an older draft from silently overwriting someone else’s work. Disconnect does not remove local content backups.

Export a backup

Export draft downloads artist-studio-draft.json, containing the artist configuration and structured pages. It contains neither the token nor your image/audio files. Export works after connecting, even before you change anything.

The current UI does not import that file. Keep it for reference or ask your repository maintainer to reconcile its artist object into artist.json and its pages object into pages.json. Do not replace the entire repository with the export.

Save draft to GitHub

Save draft creates a branch named studio/draft-<timestamp> from the revision you opened. It commits both content files together. Later saves during that connection update the same draft branch.

The live branch is unchanged. The default deployment workflow only publishes main, so draft saves do not deploy. A custom workflow must also exclude draft branches. Drafts are as public or private as the repository itself.

After reopening Studio, there is no dedicated draft-branch picker. Use local recovery when available, or inspect the draft branch in GitHub and reconcile its content with the current production files. If you connect with a draft branch as the “published branch”, Publish writes to that branch; it does not merge it into main. This is an advanced workflow, not the usual recovery route.

Publish to your website

  1. Review text, page addresses, image descriptions, navigation and colours.
  2. Check desktop and mobile previews.
  3. Select Publish.
  4. Studio validates the data and confirms the production branch has not moved since you opened it.
  5. It commits artist.json and pages.json together, then updates the branch without force.
  6. The site’s existing Pages workflow builds and deploys the website.
  7. Studio checks the live build-info.json for the commit it published before reporting that the changes are live.

You can continue editing after the commit completes while deployment runs. Those newer edits remain unpublished. Publishing does not wait for audio analysis and does not require an Actions permission on your token.

Understand publication status

MessageMeaning
Unpublished changesYour current content differs from the last publication in this session.
Draft savedA separate GitHub draft branch contains your current content.
Committed / publishingThe production commit succeeded; Pages availability is still being checked.
LiveThe public build metadata matches the published commit.
Taking longer than expectedThe expected commit was not observed after roughly 20 minutes. This does not by itself prove deployment failed.

Another commit, such as an automated catalog refresh, may supersede your exact commit before Studio sees it. The latest site can contain your edits even if the exact-SHA check times out. Check the workflow and current content rather than repeatedly publishing.

When the repository changes

Another editor or an automated catalog refresh can advance the production branch. Studio then refuses to overwrite it. Export your work while the current tab is still open, reconnect to load the newer content, and reapply or manually reconcile your changes. Do not assume reconnecting alone will preserve every field on screen.

Undo a live publication

Use GitHub’s history to revert the specific Publish website content commit, or ask the repository maintainer to restore the previous content through a new commit. The normal Pages workflow deploys that restoration. Review the diff so unrelated later changes are preserved. Studio’s Undo button does not roll back published commits.

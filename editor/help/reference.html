ARTIST STUDIO / USER GUIDE

Maintainer reference

How the shared editor fits into an artist site, and how to adopt updates safely.

Files and ownership

File or folderOwner / role
Core editor/Shared Studio interface, GitHub adapter, validation and this manual.
Core runtime/Shared public player and visual styles. Studio is separate.
artist.jsonSite identity, configuration, entrance, theme and home copy.
pages.jsonStructured extra pages and optional custom base menu.
builder.jsonSite opt-in: enabled must be true to deploy Studio.
index.html / other HTMLArtist-owned templates and handcrafted pages.
assets/, custom.css, custom.jsArtist-owned media and extensions.
.artist-corePinned Git submodule revision of the shared core.

Enable or disable Studio

{"enabled": true}

Place that in builder.json at the site root, adopt a supporting core revision and deploy. Studio is copied to admin/. Set enabled to false or remove the opt-in to omit it on the next build. Existing admin/ source content or admin.html conflicts are rejected.

Do not add tokens, repository credentials or secret draft content to files that the build publishes. Studio does not require repository identity to be embedded in its public bundle. Help is publicly readable whenever Studio is deployed.

Structured pages

{
  "schemaVersion": 1,
  "navigation": [{"label": "Music", "href": "index.html#music"}],
  "pages": [{
    "slug": "story",
    "title": "Our story",
    "label": "Story",
    "description": "Behind the music",
    "nav": true,
    "blocks": [
      {"type": "text", "heading": "The beginning", "text": "Our story."},
      {"type": "image", "src": "assets/portrait.webp", "alt": "Artist portrait", "caption": "In the studio"},
      {"type": "link", "text": "Listen", "href": "index.html#music"}
    ]
  }]
}

Omit navigation to retain the template’s base menu. Visible generated pages are appended. Extra pages reuse the home shell and replace its main element. Text and attributes are escaped; unsafe URLs and collisions are rejected by the build as well as by Studio. Generated pages are removed automatically from the next clean output when deleted from pages.json.

Compatibility and adoption

Consumers pin the core at an exact commit. A core change alone does not update their production sites. Update the submodule, build and check the candidate, then commit the pin to adopt it. Existing sites without the opt-in keep their existing editing workflow. Artist-owned HTML is not migrated automatically; unknown configuration fields are retained when editing.

Publication contract

Draft branches must not trigger production deployment. Publish writes directly to the configured branch and requires its current head to match the editor’s base. Both content files are committed in one tree, then the branch is advanced without force. PR-based publication is not implemented.

The shared build action supplies the checked-out site revision as ARTIST_SITE_SHA; build-info.json exposes it as siteCommit. Custom build workflows should set that variable to git rev-parse HEAD so the editor can verify the deployed revision accurately, especially for workflow_run events.

The saved-data build has no audio analysis or model download. It copies the existing renderer and renders content. Pages queue and propagation time still apply.

Source privacy

A static published site exposes the files deployed to it. A private source repository prevents public browsing of the repository, but does not make deployed content secret. Private-source Pages availability depends on the GitHub account plan. Draft branches in a public repository are public. A hidden navigation item is not access control.

Local checks

python -m unittest discover -s tests
node --test tests/editor.test.mjs
node --check editor/studio.mjs
python scripts/build.py --site /path/to/artist-site --output /path/to/output

Inspect the generated admin/help pages, desktop/mobile editor layouts, and the deployed audio/navigation experience after adopting a release. Keep site identities and assets out of shared editor code.
